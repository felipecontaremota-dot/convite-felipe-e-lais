# Conferência do escopo: famílias, convidados e localização

Checklist do pedido, conferida contra a implementação e os testes. As referências de testes descrevem execução local com PostgreSQL descartável, demo e HTTP simulado; não são homologação de produção/dispositivo.

| Item do pedido          | Implementação / evidência                                                                                                                                                                                          |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1. Texto de senha       | Somente a mensagem em AccountScreen mudou para “Senha atualizada.”; assertions de recovery preservadas com o novo texto.                                                                                           |
| 2. Enter no login       | Button/onSubmitEditing usam submit compartilhado, returnKeyType=go e ref de bloqueio imediato. E2E testa uma única requisição durante busy.                                                                        |
| 3. Aba ativa e Choice   | usePathname, aria-current/selected, champagne e contraste; E2E verifica as nove abas e um Choice real.                                                                                                             |
| 4. Terminologia         | Labels, mensagens e copiar link + senha usam Senha. Nomes técnicos pin/PIN_SAVE permanecem. Busca de palavra PIN no app não encontrou texto visível.                                                               |
| 5. Unidade de acesso    | invitations.kind FAMILY/INDIVIDUAL; invitation_id obrigatório; constraint diferido protege cardinalidade individual.                                                                                               |
| 6. Dados existentes     | Teste antes/depois da migration compara guest, RSVP, código/hash, senha, sessão e histórico sem mudanças.                                                                                                          |
| 7. Cadastro             | Lista primeiro, Adicionar convidado abre formulário; Nome, criança, dropdown vínculo, WhatsApp mascarado, e-mail opcional e Observações privadas.                                                                  |
| 8. Campos retirados     | Sem Família, acompanhante ou adolescente no cadastro/payload novo. GUEST_UPDATE define legado adolescente=false.                                                                                                   |
| 9. Botões               | Cadastro/edição usam Salvar e Cancelar.                                                                                                                                                                            |
| 10. Individual          | GUEST_CREATE transacional cria unidade, guest, RSVP PENDING, contato, senha string e código/hash. SQL verifica telefone/fallback/zeros iniciais.                                                                   |
| 11. Link do convidado   | Ficha oferece senha/status/link/cópia/regeneração/revogação. Membro FAMILY usa a unidade compartilhada; acesso individual anterior é arquivado. Cache antigo de código continua disponível no dispositivo emissor. |
| 12. Lista/filtros       | Ordenação localeCompare pt-BR, busca e oito filtros na ordem solicitada. E2E e unitários cobrem ordenação, busca e vínculo/RSVP.                                                                                   |
| 13. Linha               | Nome clicável, tags de vínculo/FAMILY/RSVP/criança, indicador ! com label, SVG de cópia e lixeira; notas não aparecem na linha. Exclusão é global e confirmada.                                                    |
| 14. Seleção múltipla    | Checkbox compacto somente desktop ou modo seleção; mobile inicia por long press ou alternativa na ficha; barra de associação/exclusão em lote. E2E verifica os dois caminhos e ausência de overflow.               |
| 15. Ficha               | Nome, criança, vínculo, WhatsApp/e-mail, notas, família/acesso individual, RSVP, senha/link, envio e ativação. Editar não move família.                                                                            |
| 16. Famílias            | Cards fechados com nome, membros/RSVP, responsável/telefone, senha/status, link/dispositivos/envio.                                                                                                                |
| 17. Editar família      | Lápis acessível expande nome/ativa/responsável/telefone derivado e controles de senha/link/dispositivos.                                                                                                           |
| 18. Senha familiar      | Card fechado mostra somente Senha configurada/não configurada; dígitos apenas na edição.                                                                                                                           |
| 19. Membros             | Abrir ficha, lápis de edição e remover da família. Remoção preserva guest/RSVP/contato/notas/histórico e cria acesso individual; QR anterior é revogado.                                                           |
| 20. Adicionar membros   | Ícone pessoa+, seleção de individuais; destino precisa de senha/link ativos. Operação transacional revoga sessões de origem/destino. Transferência de outra FAMILY exige confirmação na ação em lote.              |
| 21. Excluir família     | Lixeira com confirmação; soft-delete e conversão de todos os membros para INDIVIDUAL, com novos acessos e dados preservados.                                                                                       |
| 22. Juntar/dividir      | Ausentes na UI; wrapper público rejeita FAMILY_MERGE/FAMILY_SPLIT. Testes antigos dessas ações passaram a verificar rejeição explícita.                                                                            |
| 23. FAMILY × convidados | Toda pessoa tem unidade de acesso; individuais não aparecem como famílias. Contadores FAMILY do painel filtram kind.                                                                                               |
| 24. Local admin         | Nome/Endereço/Link de GPS, validação HTTPS, campo separado e version; latitude/longitude retiradas da interface, dados legados preservados.                                                                        |
| 25. Local convidado     | Abrir localização, Maps/Waze/Uber documentados, GPS, copiar/compartilhar; 99 via sistema. canOpenURL nativo e fallbacks testados com dependência simulada; Web não enumera apps.                                   |
| 26. Migration           | Somente nova 202610090004_access_units.sql; as três migrations anteriores permanecem intactas.                                                                                                                     |
| 27. RPC                 | Novas ações compostas executam no banco; helper e implementação anterior têm EXECUTE revogado aos clientes.                                                                                                        |
| 28. Concorrência        | Version de guest/família/evento, array de versões em lotes e validação antes de mutar; payload da confirmação captura versões revisadas. Campos abertos conservam versão inicial.                                  |
| 29. Auditoria           | Eventos explícitos de criação/edição/exclusão/movimentação/links/senha/dispositivos; somente IDs, sem credenciais ou detalhes privados no metadata.                                                                |
| 30. Link/senha          | Código aleatório na URL; senha separada. Copiar ambos gera duas linhas; E2E/SQL verificam ausência de senha em URL/audit.                                                                                          |
| 31. Responsividade      | Tema atual preservado, cards sob demanda, lista compacta e seleção mobile. Dropdown nativo usa modal com scroll; checks Web 390px/desktop/tablet.                                                                  |
| 32. Ícones              | SVG já disponível, labels acessíveis em lápis/lixeira/pessoa+/cópia e indicador !. Sem nova dependência.                                                                                                           |
| 33. Cobertura           | Unitários, SQL/RLS/upgrade, browser demo/Auth e regressões existentes de recovery, QR/check-in, presentes, mensagens e notificações.                                                                               |
| 34. Validações          | npm ci; lint/typecheck/unitários/Functions/banco/E2E; build/export raiz e Pages; exports Android/iOS e introspecção das queries nativas. APK/IPA/dispositivo não foram testados.                                   |
| 35. Limites             | Nenhum envio externo, arte, cronômetro, módulo novo de presentes/mensagens/notificações/check-in/Sheets ou domínio. Recovery só muda o texto de sucesso.                                                           |
| 36. PR/implantação      | Um PR sem merge automático; aplicação da migration e homologação por operador Supabase após o merge, conforme access-units.md.                                                                                     |
